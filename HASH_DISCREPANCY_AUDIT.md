# Hash discrepancy audit

## Summary

An independent byte-level sweep of JSON path-to-SHA-256 maps found the same **19 existing-file mismatches** in both the read-only source clone and the prior supplement. Their preserved fingerprints and current classifications are listed in `reproducibility/HISTORICAL_SOURCE_DRIFT.json`; no additional existing-file map mismatch was found. A historical-drift explanation was not accepted without proof: expected file contents were checked against reachable source objects and the preserved recovery archive.

| Classification | References |
| --- | ---: |
| `serialization_difference` | 15 |
| `expected_historical_version_difference` | 3 |
| `genuine_artifact_discrepancy` | 0 |
| `unresolved` | 1 |

The 15 serialization cases are limited to renderer/table-presentation changes. Six expected digests (four historical script versions, one failed evaluator, and one pre-recovery config) are supported by exact byte matches in source Git history or already-preserved historical files. The expected `prepare_safe_baselines.py` bytes were not found; that one case remains unresolved. No SHA field, result, or scientific input was changed.

## Scope and method

Compared `tmlr-supplement-source/` (read-only) and `previous/TMLR_Supplement/`, using raw-file SHA-256 over the current path in each tree. A recursive sweep of JSON maps whose keys are file paths and whose values are 64-hex digests covered **36 maps / 378 references per tree**; the only existing-path mismatches were these 19 in each tree. All 19 field values equal their `historical_recorded_sha256`; all 19 `inspected_source_sha256` values and all 19 `package_sha256` values in the prior drift report independently match the respective current files. The one current source/package byte divergence is `scripts/render_recursive_reuse.py` (one image-metadata argument line); all other current source/package target bytes are equal.

The source Git inspection covered all reachable history (76 commits; 1,120 unique reachable blobs). Exact expected bytes for four target scripts were found in historical Git trees at their recorded paths. The expected LongEmbed evaluator digest and pre-recovery configuration digest were found as preserved recovery files. The preparer digest was not found in any reachable blob or the inspected recovery archive. Git commit/object identifiers are intentionally omitted.

## Classification evidence and exact changes

- **Serialization differences (rows 1–15).** The four expected script digests are exact matches to historical source Git blobs. Their current-vs-historical source diffs are in table rendering only: `scripts/evaluate_safe_baselines.py` and the three renderer modules move TeX captions/labels from after `\end{tabularx}` to before the table; continuation caption wording also changes, and the recursive-reuse renderer has minor explanatory wording changes. The score computations, saved `RESULTS.json` values, and inference are not changed by those diff hunks. Separately, the prior package's current `scripts/render_recursive_reuse.py` differs from the current source clone in only one `fig.savefig` metadata argument; that is a package metadata serialization change, not a result or plot-data change. The historical recursive renderer exact bytes are present in source Git but were not copied into the reviewer-safe recovery bundle because the image metadata contains identifying content.
- **Expected historical versions (rows 16–18).** The LongEmbed digest exactly matches `reproducibility/protocols/review_completion_v1/recovery/evaluate_longembed_pre_scoring.py`; the recovery record identifies the pre-score FP16 summation overflow and says no scores were available before repair. Current code uses a uniform FP32 masked-mean path. The two old config digests exactly match `reproducibility/protocols/review_completion_v1/PRE_RECOVERY_CONFIG.yaml`. `TRAIN_POPULATION_RECOVERY.json` records the change from 500 fit + 100 validation rows per corpus to 160 + 40 after a fixed-range availability shortfall, and explicitly states that no embeddings, model fits, or new evaluation scores existed before that change.
- **Unresolved (row 19).** The expected preparer digest is absent from all reachable source Git blobs and the inspected historical archive. `PREPARATION_RECOVERY.json` says the failed initial attempt ended before cache or comparison metrics and describes the dtype-preflight correction, but that description is not proof of the exact expected file bytes or the precise patch. Do not replace the digest with the current preparer hash or claim the historical source is recovered.
- **Genuine artifact discrepancy.** None was established among these 19 references. This finding does not certify all saved metrics; it classifies the file-hash differences and their evidence only.

## Consumer impact and safe next steps

- The stale bindings are operational, not merely cosmetic: `scripts/audit_safe_baselines.py` runs `require_hash` over `RESULTS.json.source_sha256`; `scripts/evaluate_recursive_reuse.py`, `scripts/evaluate_reconstruction_calibration.py`, and `scripts/evaluate_continuation_comparison.py` recheck source hashes while loading their saved inference manifests. Their current readers/auditors therefore reject those saved snapshots when the current renderer/evaluator bytes differ, even where the recovered patch is only presentation. The failed LongEmbed protocol, the two failed preparation protocols, and `PREPARATION_RECOVERY.json` are archival failure records; no active consumer of those old source maps was found.
- Preserve every historical value and the original result files. Do not relabel an old SHA as current, edit frozen result JSON, or replace the old records with a new source hash. If a current-code audit is required, perform it in a new, explicitly versioned audit/output record; retain the existing source binding as historical provenance. For presentation-only renderer changes, report the exact TeX/metadata delta separately from numerical evidence. Keep the identity-bearing historical renderer version out of reviewer-facing recovery copies.
- Preserve the failed LongEmbed/config hashes and their exact archived versions as historical. Leave the initial safe-baseline preparer SHA unresolved unless the exact source is recovered from an independent archive; then verify its bytes against that SHA before considering a copy.

## Other frozen config/hash dependencies

No additional existing-file mismatch was found in the safety-critical active config pins checked in either tree. Within each tree, all existing file targets matched their own configured digest for:

- `configs/official_v6.yaml`: the attack config, normalized final/development JSON provenance files and checksum lists, and the three per-seed freeze JSON files. The pinned checkpoint/probe paths are external release artifacts, not present at the configured `artifacts/v1-paper/` path in either tree.
- `configs/safe_baselines_v1.yaml`: the official result and fixed attack config.
- `configs/recursive_reuse_v1.yaml`: baseline config/results/inference and the exact-four config.
- `configs/reconstruction_calibration_v1.yaml`: tree config and all four immutable input files.
- `configs/continuation_comparison_v1.yaml`: calibration config and all four immutable input files.
- `scripts/review_common.py::PREVIOUS`: all five immutable result JSON pins.

The package's anonymized official/result copies have different digests from the source clone, but their local config pins match their own files; this is not byte identity across trees. During the historical comparison only six probes were included and the configured full checkpoint paths were absent. The released checkpoint collection is now publicly downloadable through CHECKPOINT_ACCESS.md, without rewriting any source/experiment hash in this audit. Restoring those files does not supply absent safe-baseline/review-training caches or resolve the inherited source-fingerprint guards.

## Are fresh chained reruns usable as shipped?

**Not directly from either inspected tree.** The saved result directories already exist; the configs pin fixed output namespaces, and the additional-review helper is create-only. The existing safe-baseline inference manifest takes the “verify existing inference” path, which encounters stale source fingerprints rather than rebuilding. Downstream configs pin the current upstream result/manifest digests, so a regenerated upstream result would need an explicit downstream rebind in a new protocol chain. The required model checkpoints and caches are not materialized in these trees either. A fresh chain is possible only as a deliberately staged, separate run with the required pinned assets/data/cache and a new, coherently re-bound output/provenance chain; it is not a safe one-command rerun of the frozen outputs. No cache generation, training, expensive experiment, test, or mutation of the source/prior supplement was performed.
