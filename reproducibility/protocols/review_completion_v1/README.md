# Additive review completion v1

**Scope:** additive, post-review; the `official-v6` and all four earlier comparison result files retain their original SHA-256. This is not a new confirmatory study on untouched safe documents, a from-scratch rerun, or an objective ablation of the historical continuation. Fixed protocol: `configs/review_completion_v1.yaml`; scientific interpretation: `paper/REVIEW_EVIDENCE_MAP.md` and `paper/main.tex`. The five new result namespaces are `results/{input_order,tree_families,probe_families,decoder_gradient,longembed_review}_v1/`, with create-only configuration/source fingerprints, scores, audits, and artifact hashes. Tensors/caches are ignored by Git and uniquely hashed.

## Preparation and frozen inputs

1. Download and verify the **existing** source/final checkpoints and source/candidate TRAIN probes from `v1-paper` using `scripts/materialize_release_artifacts.py` and the original `reproducibility/ARTIFACT_MANIFEST.json` (unchanged).
2. Regenerate/verify the safe cache with the prior four post-review protocols. The safe-cache documents are 1,000 per corpus, corpus-index range [162000,192000); 606 have exactly four leaves.
3. `python scripts/prepare_review_train.py` selects 160 *fit* and 40 *unused validation* exact-four prefixes per corpus from indices [140000,152000), excluding matching safe-prefix exact-token hashes globally. Freeze exact dataset revisions, corpus order, tokenization and 1,024-token leaf construction. 800 TRAIN-role/validation-role documents; 640 TRAIN-only fits; no candidate/result-driven selection. The fit/validation sample file, full selections, SHA-256, and zero exact-token overlap are in `cache_review_train_v1/` and `results/probe_families_v1/TRAIN_MANIFEST.json`.
4. Originally 500 fit + 100 validation per corpus were specified. An interrupted pre-encoding attempt followed by an insufficient-FineWeb-population attempt produced no embeddings or scores. Both failures, logs and the original config were preserved. `TRAIN_POPULATION_RECOVERY.json` documents the only count change **before** any new model fitting or evaluation. Ranges and selection rules were not changed.

## Studies / re-execution

- `python scripts/evaluate_input_order.py`: frozen checkpoint/probe inference; 24 permutations x 606 safe prefixes x three seeds; moving/equal token masses and fixed-parent cancellation. Does not claim reordered-text teacher targets.
- `python scripts/evaluate_tree_families.py`: five ordered binary trees with unchanged four leaves, plus matched 1,024/512/256-token new leaves and K2/K4/flat baselines, teacher targets frozen.
- `python scripts/evaluate_probe_families.py`: 45 newly fitted, 400-step, TRAIN-only fixed-budget probes. Three probe seeds per bounded/unbounded/direct family, each on three learned parents and two pooled representations; equal optimizer and schedule within seed, no validation/test model selection. These are not the unavailable historical matched-pooling probes.
- `python scripts/evaluate_longembed_review.py`: original pinned-revision, full-task, FP32-reduction protocol; created the completed first three tasks but encountered JSONL Unicode separators before the fourth. **For the exact recorded completion only**, `python scripts/complete_longembed_review.py` verifies preserved task files byte-for-byte, reads physical JSONL lines, and completes the fourth. The complete task scores and retrieval vectors are sealed. Avoid rerunning into an existing namespace. For future fresh runs, combine the physical-line parser from the completion script with FP32 masked-mean accumulation from the original script in a *new* separately named namespace, and do not claim the existing protocol/source SHA-256 is reproduced by a changed implementation. A first pre-scoring run with legacy FP16 masked-mean accumulation overflowed and was archived; see recovery records below. Four task dataset file SHA-256s, scores, and document metadata are in the final JSON.
- `python scripts/evaluate_decoder_gradient.py`: 300 decoder-only updates for one shared warm checkpoint per inherited source seed; 100 identical joint minibatches with attached or detached decoder-parent gradient; six new step-400 models fixed before safe evaluation. Original remaining losses are held active. Does **not** remove all decoder training or recreate historical continuation.

Dataset access requires hosting terms/network; use Python 3.12 with `requirements.txt` and a CUDA-capable device for the recorded scripts. Each study is create-only; never remove or overwrite a failed namespace to hide an interruption. Reproduction means matched identities and numerical agreement, not identical historical embedding bytes or bit-identical GPU training across machines. No label-based retrieval parameter tuning occurred.

## Audit

`python scripts/audit_review_completion.py` independently checks each frozen output, rescores raw predictions, validates retrieval rankings and query-cluster bootstrap, verifies output and previous-result digests, checks TRAIN roles and matched schedules, and recomputes paired AUC intervals. Run `python -m pytest -q`, `uv pip check --python .venv/bin/python` and compile the LaTeX manuscript separately. The five `AUDIT.json` reports identify the checked results hashes; commands and exact validation results are in `VALIDATION.md`. The `v2-paper-review` release carries new fitted model/probe weights and the PDF, not source-corpus text or enormous derived vector caches. See `reproducibility/REVIEW_RELEASE_MANIFEST.json` for distinction from the immutable `v1-paper` weights.
